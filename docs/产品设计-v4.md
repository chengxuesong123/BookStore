# 图书商城 第四版 — 设计文档（1000 本书库 · 自动封面 · 用户管理）

> 版本：v4.0　状态：已实现　基线：v3.0（提交 `efa5a58`）
> 一句话：**把书库从 18 本扩到 1000 本，封面交给 Open Library / Google Books 自动找，后台补上用户管理，顺手修掉头像上传不显示。**

## 1. 本版需求拆解

| # | 需求 | 落点 |
|---|---|---|
| 1 | 书库约 1000 本，每个分类不少于 10 本 | 种子数据生成器 + 1000 条种子 |
| 2 | 封面优先 Open Library，找不到用 Google Books | `CoverService` + 自动封面管线 |
| 3 | 后台新增图书时按书名自动取封面，删掉手填封面 | 图书表单 + Admin Book API |
| 4 | 前台必须显示封面 | 统一封面渲染工具（图片 / 渐变 / 确定性占位） |
| 5 | 换头像后用户中心和导航栏都要显示 | 修复上传请求头 + 图片 key 刷新 |
| 6 | 后台用户管理：看信息、改信息 | `/admin/users` 页面 + Admin User API |

## 2. 数据与书库

### 2.1 规模

- 6 个分类：文学 / 历史 / 科技 / 经济 / 童书 / 社科
- 共 **1000 本**，分布 167/167/167/167/166/166，每个分类都远超 10 本
- 生成方式：`server/database/generate_seed.php`
  - 每类先放 8 本真实书目（沿用 v1 的 18 本精选 + 补充）
  - 其余用「词根 + 后缀」组合生成书名，作者/出版社/价格/库存/标签按标题哈希确定性生成
  - 标题在全局去重，重复时追加卷次
- 结果写入 `server/database/seed.sql`（约 210 KB），`php think db:init --seed --force` 一条命令重建

### 2.2 为什么封面不写进种子

1000 次外部 API 调用既慢又容易被限流，而且失败会拖垮导入。种子里 `cover` 留空，由两条路径补齐：

1. 后台新增/改名时实时取；
2. 手动跑 `php think cover:backfill --limit=100 --offset=0` 批量补。

## 3. 封面自动获取

### 3.1 优先级与接口

```
书名（+作者）
  └─ Open Library Search API
       GET https://openlibrary.org/search.json?title=…&author=…&limit=5
       → docs[].cover_i → https://covers.openlibrary.org/b/id/{cover_i}-L.jpg
  └─ 找不到 → Google Books
       GET https://www.googleapis.com/books/v1/volumes?q=intitle:…+inauthor:…
       → items[].volumeInfo.imageLinks.thumbnail（http 自动升 https）
  └─ 都失败 → 存空字符串，前端用确定性渐变占位
```

### 3.2 实现

- `server/app/service/CoverService.php`
  - `find($title,$author)`：清洗书名 → Open Library → Google Books
  - 解析逻辑拆成 `parseOpenLibrary()` / `parseGoogleBooks()`，可离线单测（`tests/cover-parse.php`）
  - cURL：连接 3s、总超时 5s、跟随 3 次跳转、带 UA；任何失败返回空串，绝不抛异常阻塞保存
- `server/config/cover.php`：开关、超时、两个接口地址都可用环境变量覆盖（方便接代理/私有网关）
- `server/app/command/CoverBackfill.php`：`php think cover:backfill`，支持 `--limit/--offset/--sleep`

### 3.3 后台表单变化

- 删除「封面（CSS 渐变或图片地址）」输入框
- 保存时由服务端取封面；编辑时仅在 **书名或作者变化、或原封面为空** 时重新取，避免每次保存都打外部接口
- 响应里返回 `cover`，表单展示只读预览，并说明「不用手填，系统按书名自动获取」

### 3.4 前台渲染

新增 `bookstor/src/utils/cover.js`：

```js
coverStyle(book)
  ├─ http(s) / /uploads / data:image → background-image + cover
  ├─ 含 gradient → 直接作为 background
  └─ 空封面 → 按书名哈希生成稳定 HSL 渐变（同一本书永远同一色）
```

所有出现书封的地方统一走它：首页书卡、Hero 漂浮、分类 mini-book、详情封面、购物车缩略图、订单明细、后台订单详情。

## 4. 头像上传修复

### 4.1 根因

`Account.vue` 上传时手写了 `Content-Type: multipart/form-data`，浏览器不会补 boundary，服务端解析不到文件（表现为：上传没反应 / 不显示）。同时头像 `src` 变化时 Vue 可能复用旧 `<img>`。

### 4.2 修复

- 去掉手写 Content-Type，让浏览器自动生成 boundary
- 头像 `<img>` 加 `:key="auth.user.avatar"`，新 URL 必刷新
- 上传成功后 `auth.setUser(响应.user)`，用户中心预览与导航栏共用同一份 Pinia 状态
- Mock 模式把文件读成 dataURL 存 localStorage，同样即时显示

## 5. 后台用户管理

### 5.1 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/users` | 列表：`q`（邮箱/昵称）、分页；带 `order_count` |
| PUT | `/api/admin/users/{id}` | 改昵称、角色、可选重置密码 |

规则：

- 昵称 2–20 字；角色只能是 `customer/admin`；密码留空不改，填了必须 ≥6 位
- 不能改自己的角色；系统至少保留一个管理员
- 接口不返回 `password_hash`
- 角色变更后对方需重新登录（会话里存的是旧角色）

### 5.2 页面

`/admin/users`：搜索、表格（ID/头像/邮箱/昵称/角色/订单数/注册时间）、行内「编辑」打开编辑卡片；侧边栏与概览快捷入口都加了入口。

## 7. 环境与限制

- **网络可达性**：Open Library / Google Books 在部分网络环境不可达。本机实测 `openlibrary.org` 超时、Google 不可达。因此：
  - 服务端超时 5s，失败静默回退，不影响保存与浏览；
  - 需要通过代理时，改 `.env` 里 `COVER_OPENLIBRARY_SEARCH` / `COVER_GOOGLE_BOOKS` 即可；
  - 部署到能访问外网的环境（或挂代理）后跑 `cover:backfill`，封面会逐步补齐。
- 1000 本书的新增封面走批量命令，不要指望一次导入全量拉取。
- 后台没有做头像裁剪、用户删除（保留历史订单归属），需要再加。
