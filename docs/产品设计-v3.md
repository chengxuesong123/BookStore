# 图书商城 第三版 — 设计文档（首页修复 + 交互打磨 + 可独立演示）

> 版本：v3.0　状态：已实现　基线：v2.0（提交 `72646dc`）
> 一句话：**修好首页「没有书」的渲染问题，把导航栏细节调顺，再给一套不依赖后端的可点 Demo。**

## 1. 本版要解决的问题

v2 上线后截图暴露出的实际问题：

| # | 问题 | 现象 | 根因 |
|---|---|---|---|
| 1 | 首页没有图书 | 「新书上架」整块空白，书卡看不到 | v1 样式 `.book-card { opacity: 0 }`，靠 JS 加 `.in` 入场；v2 换成 Vue 后没人加这个类 |
| 2 | Hero 书堆错位 | 右上角变成一行挤在一起的文字 | 组件用了 `.float-book`，样式里实际是 `.book-float` |
| 3 | 分类卡错位 | 封面色条压在文字上 | 组件结构用了 `.promo-cover`，样式要求 `.promo-card > .mini-book` + `promo-mint/peach/sky` |
| 4 | 头像偏小 | 36px，视觉上比导航文字弱 | 设计要求放大 |
| 5 | 搜索框不收起 | 点开搜索后点别处仍悬浮，挡内容 | 只做了开关，没有「点外部关闭 / 路由切换关闭」 |
| 6 | 演示门槛高 | 看 Demo 要装 PHP + MySQL + 导库 | 没有 mock 数据模式 |

## 2. 设计原则（本版新增）

1. **样式契约优先**：组件类名必须和 `style.css` 对齐；不再出现「DOM 有了但看不见」。
2. **失败可见**：接口失败、数据为空都要渲染可见的空状态和重试按钮，不允许静默白屏。
3. **Demo 不依赖环境**：`VITE_MOCK=1` 时请求走浏览器内 mock，后端完全不需要启动。
4. **真模式优先**：mock 只在 mock 构建/启动时安装，真实模式零侵入。

## 3. 首页渲染修复

### 3.1 图书卡片

`BookCard.vue` 结构改回样式约定的 DOM：

```
.book-card(.in)
├── .book-cover        背景 = 书的封面渐变
│   ├── .cv-cat
│   └── .cv-title
└── .book-body
    ├── .book-title / .book-author
    └── .book-foot > .price + 库存标签
```

- 组件 `onMounted` 后延迟 `30ms + delay` 加上 `.in`，恢复「逐个上浮淡入」；`delay` 由列表 `index * 40ms` 传入。
- 书卡可见性有测试兜底：E2E 断言 `getComputedStyle(.book-card).opacity === '1'`。

### 3.2 Hero 书堆

类名改为 `.book-float`，三本分别挂 `.b1/.b2/.b3`，内部 `.bf-cat` / `.bf-title`，位置、旋转、漂浮动画全部交给 CSS，组件不再写内联定位。

### 3.3 分类精选卡

```
.promo-card.promo-mint|peach|sky
├── .promo-badge（分类名）
├── .mini-book（右侧斜放的小书封，背景 = 该书封面）
├── h3（书名）+ p（作者 · 价格）
└── .btn 去看看
```
删除 `.promo-cover` 的错误用法，三张卡颜色按 `i % 3` 轮换。

### 3.4 加载 / 空 / 失败状态

- 加载中：书区保持占位，不闪空白；
- 无数据：渲染「书还没到货」+ 原因 + 「重新加载」按钮；
- 接口失败：展示 `e.msg`（例如后端没启动）并允许重试，不再静默吞错。

## 4. 导航栏细节

| 项 | v2 | v3 |
|---|---|---|
| 头像尺寸 | 36×36 | **40×40**（移动端 36；后台顶栏 34） |
| 头像位置 | 与图标同行 | 不变，仍与搜索/购物车中心线对齐 |
| 搜索收起 | 只能再点图标 | **点击搜索框和图标之外的区域自动收起**；路由切换（点导航/书卡）也收起；提交后收起 |
| 红点 | 有商品才显示 | 不变 |

实现：`ShopLayout` 监听 `mousedown`，命中判断只看 `.search-overlay` 与搜索按钮；`onUnmounted` 解绑；`watch(route.fullPath)` 兜底。

## 5. Demo 模式（后端模拟数据）

### 5.1 开关

- `bookstor/.env.mock`：`VITE_MOCK=1`
- `pnpm dev:mock`（5174）或 `pnpm build:mock` + `pnpm preview:mock`（4174）
- `main.js`：`if (import.meta.env.VITE_MOCK === '1') installMock(http)`，把 axios 的 `adapter` 换掉

### 5.2 Mock 实现

- `bookstor/src/mock/data.js`：18 本书、6 个分类，字段与真实 API 完全一致（由数据库种子导出）
- `bookstor/src/mock/index.js`：
  - 按 `method + path` 路由到处理函数，返回同样的 `{code,msg,data}` 信封与状态码；
  - 状态存 `localStorage['moyu-mock-v3']`：用户、会话、购物车（游客/用户）、订单、图书、分类；
  - 覆盖：注册/登录/退出、资料/头像（File → dataURL）、分类、图书列表/详情（搜索/分类/排序/分页）、购物车增删改、结算预览（cart/direct）、下单（扣库存）、订单流转、后台概览/图书 CRUD/上下架/订单处理/分类管理；
  - 初始化账号：`admin@moyu.com / admin123`；数据坏了自动重建。
- 清空演示数据：DevTools 里删掉 `moyu-mock-v3` 后刷新。

### 5.3 与真实模式的一致性

Mock 只模拟「服务端行为」，前端代码不分支：页面、store、校验、提示全部走同一套。差异仅在于：

- CSRF token 固定为 `mock-csrf-token`；
- 头像存 dataURL 而不是上传文件；
- 订单号前缀 `MYDEMO`。
