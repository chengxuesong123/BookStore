# 图书商城 MVP — 产品设计文档

> 版本：v0.1　状态：待确认　范围：MVP（最小可成交版本）

## 1. 目标与定位

一句话定位：**一个人能完整跑通"上架 → 找到 → 下单 → 发货 → 完成"的图书商城**。

MVP 成功标准（验收线）：

- 顾客能浏览、搜索、加购、下单，生成订单；
- 管理员能在后台维护图书、推进订单状态直到"已完成"；
- 全流程无报错，关键操作有服务端校验。

不追求：视觉精美、流量承载、花式营销。先能成交。

## 2. 用户角色

| 角色 | 说明 | 主要行为 |
|---|---|---|
| 游客 | 未登录 | 浏览、搜索图书，加入购物车 |
| 顾客 | 已注册登录 | 下单、查看自己的订单 |
| 管理员 | 后台账号 | 图书上架维护、查看和处理订单、看库存 |

## 5. 核心流程

### 5.1 下单流程

1. 顾客在列表/详情页加入购物车（游客可加，用 session 暂存）；
2. 进入购物车，改数量、勾选要买的书；
3. 点结算 → 必须登录，未登录先跳登录并回跳；
4. 填写收货人、手机号、地址，确认订单；
5. 服务端校验库存、重算金额（**金额以后端计算为准，不信任前端**）；
6. 生成订单（待付款）+ 订单明细（书名、单价快照）+ 扣减库存；
7. 清空已结算的购物车项，跳转订单详情。

支付策略：MVP **不接真实支付**，下单即选择「货到付款」，订单直接进入待发货。真实支付留到第二版。

### 5.2 订单状态机

```
待付款 ──付款/确认──> 待发货 ──管理员发货──> 已发货 ──管理员完成──> 已完成
   │                    │
   └──顾客取消──────────┴──管理员取消──> 已取消（回补库存）
```

状态流转只允许后台操作（除顾客取消未付款订单），非法流转一律拒绝。

## 6. 数据模型（MySQL）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id, email/phone, password_hash, nickname, role, created_at | role: customer / admin |
| `categories` | id, name, sort | 单层分类 |
| `books` | id, category_id, title, author, publisher, price, stock, cover, intro, status, created_at | status: on/off 上下架；price 用 decimal(10,2) |
| `cart_items` | id, user_id, book_id, quantity, created_at | 已登录用户走库；游客可先只用 session |
| `orders` | id, order_no, user_id, receiver, phone, address, total_amount, status, created_at | 订单主表 |
| `order_items` | id, order_id, book_id, book_title, price, quantity | 存快照，图书改名改价不影响历史订单 |

约束要点：

- 库存扣减在事务里做，并用条件更新避免超卖；
- `order_items` 必须有 `book_title`、`price` 快照字段；
- 金额统一 `decimal`，不用浮点。

## 7. 技术方案

| 层 | 选型 |
|---|---|
| 后端 | ThinkPHP 8（MVC），PHP 8.3.36 |
| 数据库 | MySQL（phpstudy 自带） |
| 前端 | 原生 HTML + CSS + JS，TP8 视图模板渲染，不引前端框架 |
| 依赖管理 | Composer 2.5.8 |
| 鉴权 | 后台用中间件 + session；密码 `password_hash` |

目录约定（TP8 标准结构）：

```
app/controller/       前台控制器（Index、Book、Cart、Order、User）
app/controller/admin/ 后台控制器（Admin\Book、Admin\Order…）
app/model/            模型（Book、Order、OrderItem…）
app/middleware/       鉴权中间件
view/                 模板（前台 + 后台）
public/               入口与静态资源（css/js/img、封面）
```

约定：控制器不写 SQL，模型层封装；服务端校验放在请求校验类或控制器入口。

## 8. 校验与安全要求

- 所有表单服务端校验（必填、类型、长度、手机号格式）；
- 价格、库存、金额一律以数据库为准，前端参数只做参考；
- 下单时校验库存，扣减用事务；
- 模板输出统一转义，防 XSS；
- 表单带 CSRF token（用 TP8 内置）；
- 密码哈希存储，登录失败不区分"账号不存在/密码错误"；
- 订单详情校验归属，后台路由必须过管理员中间件。
