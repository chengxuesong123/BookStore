# 图书商城 MVP — 产品设计文档

> 版本：v0.2　状态：已按前端 Demo 校准　范围：MVP（最小可成交版本）
> 对应原型：`demo/`（jQuery 4 前端原型，mock 数据）

## 1. 目标与定位

一句话定位：**一个人能完整跑通"上架 → 找到 → 下单 → 发货 → 完成"的图书商城**。

MVP 成功标准（验收线）：

- 顾客能用邮箱注册、登录，浏览、搜索、加购、下单；
- 管理员能在后台维护图书、推进订单状态直到"已完成"；
- 全流程无报错，关键操作有服务端校验；
- 后台入口不对普通用户开放，角色校验在服务端完成。

`demo/` 已把交互与页面结构跑通，本文档以它为准；差异见第 11 节。

## 2. 用户角色

| 角色 | 获得方式 | 主要行为 | 入口 |
|---|---|---|---|
| 游客 | 未登录 | 浏览、搜索图书，加购物车 | 前台 |
| 顾客 | 邮箱 + 密码注册 | 下单、查看自己的订单 | 前台 |
| 管理员 | 后台预置账号，不可注册 | 图书上下架、处理订单、看概览 | `#/admin`（导航不展示） |

关键规则：

- 注册只产生 `customer` 角色，**不能**注册出管理员；
- 后台入口不出现在前台导航，仅通过 URL 访问；
- 未登录访问后台 → 跳登录页并提示；已登录但非管理员 → 回首页并提示无权限；
- 管理员登录成功后直接进入后台。

## 4. 页面结构与路由

### 前台

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | Hero + 分类精选 + 新书 + 热销 + 服务承诺 |
| `/books` | 图书列表 | 搜索、分类筛选、排序 |
| `/book/{id}` | 图书详情 | 加购 / 立即购买 |
| `/cart` | 购物车 | 数量修改、结算入口 |
| `/checkout` | 确认订单 | 需登录；收货信息 + 金额汇总 |
| `/orders` | 我的订单 | 需登录 |
| `/order/{id}` | 订单详情 | 需登录，校验归属 |
| `/login` | 登录 | 邮箱 + 密码；底部有注册入口 |
| `/register` | 注册 | 邮箱、昵称、密码、确认密码 |

### 后台

后台入口**不在前台导航出现**，仅通过地址访问；登录后校验角色，非管理员一律拒绝。

| 路由 | 页面 |
|---|---|
| `/admin` | 概览 + 订单管理 / 图书管理（需 admin 角色） |
| `/admin/books/create`、`/admin/books/{id}/edit` | 图书表单 |
| `/admin/categories` | 分类管理 |
| `/admin/orders/{id}` | 订单详情 |

权限要求：`/admin` 及其子路由全部走管理员中间件；未登录跳登录页，已登录但非管理员回首页。

## 5. 核心流程

### 5.1 注册与登录

1. 登录页提供「立即注册」，跳转注册页；
2. 注册填邮箱、昵称、密码、确认密码；
3. 校验邮箱格式、邮箱未被占用、昵称 ≥2 字、密码 ≥6 位、两次一致；
4. 注册成功自动登录（`role=customer`），回到原页面或首页；
5. 登录成功后按角色分流：`admin` → 后台，`customer` → 原页面。

### 5.2 下单流程

1. 顾客在列表/详情页加入购物车（游客可加，用 session 暂存）；
2. 进入购物车，改数量、删除；
3. 点结算 → 必须登录，未登录先跳登录并回跳；
4. 填写收货人、手机号、地址，确认订单；
5. 服务端校验库存、重算金额（**金额以后端计算为准，不信任前端**）；
6. 生成订单（待付款）+ 订单明细（书名、单价快照）+ 扣减库存；
7. 清空已结算的购物车项，跳转订单详情。

支付策略：MVP **不接真实支付**，下单为「货到付款」，订单进入待付款。
Demo 用「模拟付款」按钮推进，正式版替换为真实支付回调。

### 5.3 订单状态机

```
待付款 ──付款/确认──> 待发货 ──管理员发货──> 已发货 ──管理员/顾客完成──> 已完成
   │                    │
   └──顾客取消──────────┴──管理员取消──> 已取消（回补库存）
```

状态流转只允许后台操作（除顾客取消未付款订单），非法流转一律拒绝。

### 5.4 后台权限流程

```
访问 /admin → 已登录？──否──> /login?admin=1（提示仅管理员）
                 │是
                 ▼
            role=admin？──否──> 回首页 + 提示无权限
                 │是
                 ▼
              渲染后台
```

## 6. 数据模型（MySQL）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id, email, password_hash, nickname, role, created_at | `email` 唯一；role: customer / admin |
| `categories` | id, name, sort | 单层分类 |
| `books` | id, category_id, title, author, publisher, price, original_price, stock, cover, intro, tags, status, created_at | status: on/off；价格 `decimal(10,2)` |
| `cart_items` | id, user_id, book_id, quantity, created_at | 已登录走库；游客先存 session |
| `orders` | id, order_no, user_id, receiver, phone, address, remark, total_amount, status, created_at | 订单主表 |
| `order_items` | id, order_id, book_id, book_title, price, quantity | 存快照，改名改价不影响历史订单 |

约束要点：

- `users.email` 唯一索引，注册重复直接拒绝；
- 库存扣减在事务里做，条件更新避免超卖；
- `order_items` 必须有 `book_title`、`price` 快照字段；
- 金额统一 `decimal`，不用浮点。

## 7. 技术方案

| 层 | 选型 |
|---|---|
| 后端 | ThinkPHP 8（MVC），PHP 8.3.36 |
| 数据库 | MySQL（phpstudy 自带） |
| 前端 | HTML + CSS + 原生 JS + **jQuery 4.0.0**（本地 `demo/assets/vendor/jquery.min.js`），TP8 视图渲染 |
| 依赖管理 | Composer 2.5.8 |
| 鉴权 | session + 中间件；密码 `password_hash` / `password_verify` |
| 视觉 | 浅蓝→粉紫渐变、薄荷/蜜桃/浅蓝卡片、珊瑚红主按钮、深藏青文字 |

目录约定（TP8 标准结构）：

```
app/controller/       前台控制器（Index、Book、Cart、Order、User）
app/controller/admin/ 后台控制器（Admin\Index、Admin\Book、Admin\Order）
app/model/            模型（Book、Order、OrderItem、User…）
app/middleware/       AdminAuth（角色校验）
view/                 模板（前台 + admin）
public/               入口与静态资源（css/js/img、封面；jquery.min.js）
```

约定：控制器不写 SQL，模型层封装；服务端校验放在请求校验类或控制器入口。

### 视觉与交互规范（来自 Demo）

- 主色：珊瑚红 `#e8515f`（按钮/价格）；深藏青 `#1f3a5f`（标题/主按钮）
- 辅色：薄荷 `#d9f0e8`、蜜桃 `#ffe3d3`、浅蓝 `#dbeafe`、粉紫 `#ece9fe`
- 圆角：卡片 16–18px，按钮胶囊形；阴影轻、留白多
- 动效：卡片逐个上浮淡入、页面切换淡入、购物车角标弹跳、Toast 滑入、头部滚动收缩、Hero 书堆漂浮、表单错误抖动
- 响应式：1200px 内容宽；≤1024px 收为单列；≤760px 两列书卡、隐藏部分辅助信息

## 8. 校验与安全要求

- 所有表单服务端校验（必填、类型、长度、邮箱格式、手机号格式）；
- 邮箱唯一性在数据库层兜底；
- 价格、库存、金额一律以数据库为准，前端参数只作参考；
- 下单时校验库存，扣减用事务；
- 模板输出统一转义，防 XSS；
- 表单带 CSRF token（用 TP8 内置）；
- 密码哈希存储，登录失败不区分"账号不存在/密码错误"；
- 订单详情校验归属；**后台路由必须过管理员中间件，不能只靠前端隐藏入口**。
