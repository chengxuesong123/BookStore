# 图书商城 第二版 — 产品与技术设计文档

> 版本：v2.0（设计稿）　状态：待评审　基线：v1.0 MVP（提交 `a9d4ccf`）
> 目标：在已跑通的 MVP 上做**前后端分离**，并完成 5 项前端交互改版与后台可用性修复。

## 1. 版本目标

一句话：**同一套业务，拆成「前端 SPA + 后端 API」，顺手把用户看得见、用得烦的地方改掉。**

本版验收线（对应本次需求）：

| # | 需求 | 验收标准 |
|---|---|---|
| 1 | 前后端分离 | 前端独立在 `bookstor/`，后端独立在 `server/`；前端可单独 `dev` 启动，后端只输出 JSON |
| 2 | 导航图标改版 | 搜索、购物车换成简约线性图标，尺寸放大，垂直对齐 |
| 3 | 购物车红点 | 空车无任何标记；有商品才出现红点（带件数） |
| 4 | 用户头像 | 顶部用户按钮变头像；点击进入用户中心，可改头像、昵称 |
| 5 | 立即购买 | 点「立即购买」直达确认订单页，不写购物车、不清购物车 |
| 6 | 后台不迷路 | 后台有固定侧边栏与面包屑；管理员在前台随时能回到后台；刷新/直链可达 |

## 2. 与 v1 的关系

- v1（服务端渲染 TP8 + think-template）已完整跑通，作为**业务基线**保留：打 tag `v1.0-mvp`，代码继续留在 Git 历史里。
- v2 不复用 v1 的模板层（`view/`、`public/static`），但**复用业务逻辑**：模型、校验规则、购物车合并、事务扣库存、订单状态机、CSRF、鉴权中间件全部迁移到 API 层。
- v1 的 `demo/` 仍只作原型参考，不参与运行。

## 3. 角色与权限（变化点）

角色定义不变（游客 / 顾客 / 管理员），变化的是**入口可见性**：

| 项 | v1 | v2 |
|---|---|---|
| 后台入口 | 前台导航完全隐藏，只能手输 URL | 普通用户仍完全不可见；**管理员**在前台头像菜单与用户中心可见「进入后台」 |
| 后台布局 | 顶部几个 tab，点「返回前台」就离开后台 | 固定侧边栏 + 面包屑，后台内部跳转不丢失上下文 |
| 权限校验 | 服务端中间件 | 服务端中间件（`/api/admin/*`）+ 前端路由守卫（仅体验，不作为安全边界） |

> 说明：v1 的「后台入口不出现」是为了防普通用户误入；v2 的目标是「普通用户看不见，管理员找得到」，这两件事不冲突。管理员可见入口不构成越权，真正的边界仍在服务端。

## 5. 接口设计

### 5.1 约定

- 前缀：`/api`；全部 JSON。
- 统一响应：

```json
{ "code": 0, "msg": "ok", "data": {} }
```

- 错误：`code` 非 0，同时给对应 HTTP 状态。

| HTTP | code | 含义 |
|---|---|---|
| 400 | 40000 | 参数错误 |
| 401 | 40100 | 未登录 |
| 403 | 40300 | 无权限（非管理员） |
| 404 | 40400 | 资源不存在（含订单不属于当前用户） |
| 419 | 41900 | CSRF 失效 |
| 422 | 42200 | 校验失败，`data.errors` 为字段级错误 |
| 500 | 50000 | 服务端异常 |

- 分页：`data = { list, total, page, page_size }`。
- 认证：沿用 **Session Cookie**（`PHPSESSID`），前端 `withCredentials`；不引入 JWT，避免多一套令牌与刷新逻辑。
- CSRF：`GET /api/auth/csrf` 取 token，写请求带 `X-CSRF-Token` 头；服务端校验失败返回 419。
- 跨域：开发期前端 `vite.config.ts` 把 `/api` 代理到 `http://127.0.0.1:8124`，生产由 Nginx 同域转发，**两端始终同源**，不用通配 CORS。

### 5.2 接口清单

**认证 / 用户**

| 方法 | 路径 | 说明 |
|---|---|---|

| POST | `/api/user/avatar` | 上传头像（multipart） |
| POST | `/api/user/password` | 改密码（P2，本版可后置） |

**商品**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/categories` | 分类列表 |
| GET | `/api/books` | `q, cat, sort, page, page_size` |
| GET | `/api/books/{id}` | 详情 + 同类推荐 |

**购物车**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/cart` | 行 + 金额汇总（服务端算） |
| POST | `/api/cart/items` | `{book_id, qty}`；游客走 session，登录走库 |
| PATCH | `/api/cart/items/{book_id}` | `{qty}`，0 视为删除 |
| DELETE | `/api/cart/items/{book_id}` | 删除一行 |

**结算 / 订单**

| POST | `/api/orders/{id}/cancel` | 待付款 → 已取消，回补库存 |
| POST | `/api/orders/{id}/receive` | 已发货 → 已完成 |

**后台**（全部过 `AdminAuth`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/stats` | 图书/在售/订单/待发货 |
| GET | `/api/admin/books` | 含下架，支持 `q` |
| POST | `/api/admin/books` | 新增 |
| GET | `/api/admin/books/{id}` | 编辑回显 |
| PUT | `/api/admin/books/{id}` | 更新 |

| DELETE | `/api/admin/books/{id}` | 删除（清购物车引用） |

| GET | `/api/admin/orders/{id}` | 订单详情 |

## 6. 前端页面与路由

### 6.1 路由表（Vue Router，history 模式）

| 路由 | 页面 | 布局 | 守卫 |
|---|---|---|---|
| `/` | 首页 | Shop | 无 |
| `/books` | 图书列表（`q/cat/sort/page` 同步到 query） | Shop | 无 |
| `/book/:id` | 图书详情 | Shop | 无 |
| `/cart` | 购物车 | Shop | 无 |
| `/checkout` | 确认订单（`mode=cart\|direct&book_id&qty`） | Shop | 需登录，未登录跳 `/login?redirect=` |
| `/orders` | 我的订单 | Shop | 需登录 |
| `/order/:id` | 订单详情 | Shop | 需登录 |
| `/login`、`/register` | 登录 / 注册 | 空白居中 | 已登录访问则回首页 |
| `/account` | **用户中心（新增）** | Shop | 需登录 |
| `/admin` | 后台概览 | Admin | 需 admin |
| `/admin/books`、`/admin/books/new`、`/admin/books/:id/edit` | 图书管理 | Admin | 需 admin |
| `/admin/orders`、`/admin/orders/:id` | 订单管理 | Admin | 需 admin |
| `/admin/categories` | 分类管理 | Admin | 需 admin |
| `/:pathMatch(.*)*` | 404 | Shop | 无 |

守卫只做体验层拦截：未登录 → `/login?redirect=当前地址`；非管理员访问 `/admin/**` → 提示并回 `/`。**真正的权限仍由 `/api/admin/*` 的服务端中间件兜底。**

### 6.2 顶部导航改版（需求 2、3、4）

现状：搜索、购物车是 emoji（🔍 🛒），大小随字体、基线不齐；用户按钮是文字胶囊。

目标结构（`.header-actions`，`display:flex; align-items:center; gap:12px`）：

| 元素 | 规格 |
|---|---|
| 搜索按钮 | 内联 SVG，`24×24` viewBox，`stroke: currentColor; stroke-width: 1.75; fill: none`；渲染尺寸 `24px`；点击区 `40×40` 圆角 12px |
| 购物车按钮 | 同上线性图标（篮身 + 两个轮子），`24px` |
| 红点 | 仅 `count > 0` 渲染；直径 `18px`，红 `#e8515f`，白字件数，`>99` 显示 `99+`；绝对定位 `top:-2px; right:-4px`，带轻微弹跳 |
| 头像按钮 | `36×36` 圆形；有头像显示图片，无头像显示昵称首字 + 渐变底；点击直接进 `/account`（不做下拉菜单） |
| 对齐 | 三个按钮统一 `40×40` 命中区、`line-height:0`，与 logo、导航在一条水平中线上 |

搜索交互：点搜索图标展开顶部搜索浮层（输入框 + 回车提交），提交跳 `/books?q=…`；不新开页面。

不做的：图标库依赖（手写两个 SVG 组件即可）、彩色/拟物图标。

### 6.3 用户中心页（需求 4）

`/account`（前端路由，需登录）：

- 头像区：当前头像预览 + 「更换头像」按钮；选择文件后立即上传，成功后刷新预览与顶部头像；
- 昵称：输入框 + 保存；校验 2–20 字，保存后就地提示；
- 只读信息：邮箱、角色、注册时间；
- 快捷入口：我的订单、购物车；
- 管理员额外显示「进入后台」；
- 退出登录。

头像上传规则：

- 允许 `jpg/jpeg/png/webp`，单文件 ≤ 2MB，服务端按真实 MIME 校验（不信任扩展名）；
- 存储：`server/public/uploads/avatars/{user_id}-{random8}.{ext}`，DB 存相对路径 `/uploads/avatars/xxx.png`；
- 更换成功后删除旧文件（仅限 `uploads/avatars/` 内，文件名由服务端生成，防目录穿越）；
- 失败提示统一「头像上传失败，请换一张试试」，不暴露服务端细节。

### 6.4 立即购买（需求 5）

```
详情页「立即购买」
  → GET /api/checkout/direct?book_id=3&qty=1   （校验在售/库存，返回单行金额）
  → 跳 /checkout?mode=direct&book_id=3&qty=1
  → 未登录：先存 redirect，登录后回跳（购物车不受影响）
  → 提交 POST /api/orders {mode:"direct", ...}
  → 事务扣库存、建订单、写快照；**不读、不写、不清空购物车**
  → 跳 /order/{id}
```

边界：

- 直接购买数量受库存限制，前端数量选择器上限 = 库存；
- 提交时服务端重新校验在售与库存，库存不足返回 422，页面停留并提示；
- `mode=direct` 缺少 `book_id` 或书已下架 → 结算页显示「商品不可购买」并给回列表入口；
- 购物车结算 `mode=cart` 逻辑与 v1 一致（含登录合并、清空已结算项）。

金额与运费：沿用 v1 规则（满 59 包邮，否则 6 元），**由服务端计算并返回**，前端只展示。

### 6.5 后台可用性（需求 6）

v1 的问题：后台是"几个顶部 tab + 返回前台"，点进订单/图书后再点别的就容易离开后台上下文；刷新后也没有稳定导航。

v2 方案：

1. **独立布局**：`AdminLayout` = 左侧固定侧边栏（概览 / 图书管理 / 订单管理 / 分类管理）+ 顶栏（面包屑、当前管理员、返回前台、退出）。侧边栏高亮当前路由，内容区独立滚动。
2. **后台内跳转不重载**：SPA 路由切换，筛选条件（订单状态、搜索词、分页）保留在 URL query，刷新/前进后退可复现。
3. **入口常驻**：管理员在前台顶部头像 → `/account` → 「进入后台」；另外前台在管理员登录态下显示一个低调的「后台」chip（普通用户不渲染）。这样从后台「返回前台」后随时能回去。
4. **面包屑**：`后台 / 订单管理 / 订单 #MY2026…`，每级可点。
5. **后台 404**：`/admin/*` 未匹配路由显示后台内 404 卡片 + 「回概览」，而不是掉到前台 404。
6. **刷新安全**：直达 `/admin/orders/12` 时，守卫先拉 `/api/auth/me` 再决定渲染/跳转，避免闪一下白屏。

### 6.6 视觉与交互规范（沿用 v1）

- 颜色、圆角、阴影、动效沿用 v1（珊瑚红 `#e8515f`、深藏青 `#1f3a5f`、卡片 16–18px）；
- 图标统一线性风格，不用 emoji；
- Toast、卡片逐个淡入、按钮 loading 保持；
- 响应式断点不变（1200 / 1024 / 760）；≤760px 时头像 32px、图标 22px。

## 8. 技术方案

| 层 | v1 | v2 |
|---|---|---|
| 后端 | TP8 + think-template 服务端渲染 | TP8 **纯 API**（无视图），Session + CSRF |
| 前端 | 原生 JS + jQuery，服务端输出 HTML | **Vue 3 + Vite + TypeScript + Vue Router + Pinia + axios** |
| 样式 | 一份全局 CSS | 同一套 CSS 迁移为前端资源，组件内 scoped 补充 |
| 图标 | emoji | 内联 SVG 组件 |
| 鉴权 | session + 中间件 | 不变（Cookie 同源） |
| 测试 | Edge CDP E2E | 接口契约测试（Node fetch）+ 浏览器 E2E |

选型理由：Vue 3 生态成熟、Vite 启动快、Pinia 管登录态/购物车状态最省事；不引 UI 框架，避免为改两个图标重写视觉。**接口契约与框架无关**，若后续换 React，只需重写 `bookstor/`。

关键实现约定：

- axios 实例统一 `baseURL: '/api'`、`withCredentials: true`、自动带 `X-CSRF-Token`、401 统一跳登录、422 把 `data.errors` 交给表单；
- 登录态与购物车件数放 Pinia；页面刷新先 `GET /api/auth/me` + `GET /api/cart` 水合；
- 后端新增 `JsonResponse` 中间件统一包 `{code,msg,data}`，控制器只返回数组/抛业务异常；
- 业务异常用自定义 `ApiException(code,msg,httpStatus,errors)`，由异常处理统一转 JSON。

### 启动方式

```powershell
# 后端（8124）
cd server
php -S 127.0.0.1:8124 -t public public/router.php

# 前端（5173，/api 代理到 8124）
cd bookstor

pnpm dev
```

生产：Nginx 托管 `bookstor/dist`（history fallback 到 `index.html`），`/api` 反代到 PHP；`/uploads` 由 Nginx 直接出。

## 9. 校验与安全

- 所有写接口服务端校验，规则沿用 v1（邮箱唯一、昵称 2–20、密码 ≥6、手机号 1 开头 11 位、地址 ≥6 字）；
- 金额、库存、运费一律服务端算；下单事务 + `stock >= qty` 条件扣减；
- CSRF：写请求必须带 `X-CSRF-Token`，缺失 419；
- 越权：订单详情按 `user_id` 校验归属，越权返回 404（不暴露存在性）；`/api/admin/*` 全量 `AdminAuth`；
- 头像上传：MIME + 大小校验、随机文件名、只允许图片后缀、旧文件删除限定目录；
- 上传目录禁止执行 PHP（Nginx/PHP 内置服务器目录不放执行脚本）；
- 前端守卫只是体验，不作为安全边界。

## 13. v1 → v2 差异总表

| 项 | v1 | v2 |
|---|---|---|
| 架构 | TP8 服务端渲染 | `bookstor/` SPA + `server/` API |
| 页面渲染 | think-template | Vue 组件 |
| 页间跳转 | 整页刷新 | 前端路由 |
| 登录态 | Session + 模板变量 | Session Cookie + Pinia |

| 测试 | 110 项浏览器 E2E | 接口契约 + 浏览器 E2E |

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 目录迁移导致路径/配置失效 | 起不来 | M0 单独一步，迁移后立刻跑通健康检查接口再继续 |
| Cookie 跨端口/跨域失效 | 登录态丢失 | 开发用 Vite 代理保持同源；生产同域反代 |
| 立即购买与购物车状态串了 | 清错车/多扣库存 | `mode` 显式区分；direct 分支不触碰 `cart_items`，测试断言购物车件数不变 |
| 头像上传被滥用 | 磁盘/执行风险 | 大小与 MIME 校验、随机文件名、上传目录禁执行 |
| 后台 SPA 刷新 404 | 无法直达 | history fallback 到 index.html + 服务端兜底路由 |
| 迁移期间两版并存 | 混淆 | tag 留档，根 README 明确 v2 为主、v1 只读 |
